# チャット中心の地図をブラウザで検証する

対象は本番と同じルート `/`。Chromium で PC（1280×800）とスマホ幅（390×844）の両方を操作する。`/prototype` のデモではない。

## 実行

Node.js 24.20.0 とインストール済みのプロジェクト依存が必要。リポジトリのルートで、ターミナル1から起動する。

```sh
mise exec node@24.20.0 -- sh e2e/start-isolated.sh
```

コードと公開ファイルだけを一時ディレクトリにコピーし、元の `node_modules` を参照する。`.env*` はコピーしない。キーはすべてダミー、台帳は一時ファイル、Next.js の Google Fonts もローカルのテストフォントを使う。アプリを編集したらサーバーを再起動してコピーを更新する。

ターミナル2で実行する。Playwright はアプリの依存に含まれない。インストール済みの Playwright と Chromium を使う場合：

```sh
export PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs
export E2E_CHROMIUM_PATH=/absolute/path/to/chrome-headless-shell
(set -e; for suite in e2e/verify-*.mjs; do
  mise exec node@24.20.0 -- node "$suite"
done)
```

Playwright を通常のモジュールとして import できる場合や、対応する Chromium が標準キャッシュにある場合は、それぞれの変数を省略できる。新規導入する場合は `npm install --prefix e2e --no-save --package-lock=false playwright` と `node e2e/node_modules/playwright/cli.js install chromium`（ツールのインストールにはネットワークが必要）。

既定は `http://127.0.0.1:3107`。変更時はターミナル1で `E2E_PORT`、ターミナル2で対応する `E2E_BASE_URL` を設定する。ローカルホストの明示ポートだけを許可し、3000 は拒否する。終了時はターミナル1で Ctrl-C。

## 検証範囲

| スイート                                           | 確認すること                                                                                                                                                                                                                                                                          |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verify-root-journey.mjs`                          | 同じ入力欄から地図検索、曖昧な条件の確認、同じ ID・番号・口コミでの再評価と順位変更、新しい範囲検索への切替。徒歩比較は2店の選択時だけ送信。地図移動後も開始時の中心を共有し、失敗・再試行・所要分数・経路なしを区別する。                                                            |
| `verify-place-questions.mjs`                       | 店舗を質問先にした単一入力欄・候補質問、300字制限・変換中 Enter、支店ごとの履歴・質問対象の口コミ、複数出典の原文と投稿者、根拠なし、一覧に戻った後の候補保持。検索・採点の追加呼び出しがない。                                                                                       |
| `verify-fetch-limits.mjs` / `budget-scenarios.mjs` | 23件中先頭20件まで、同時5件、口コミなしをスキップ、一部失敗に再試行なし。新しい検索による通信中断と、受信済みの古い応答の破棄。予算の月・セッション・実行上限、台帳障害で次のバッチを開始しないことと、上限ごとの再検索可否。                                                         |
| `verify-detail-panel.mjs`                          | 地図対象で開く手動フォーム、準備・検索・評価の run ID の一致、シートのドラッグ・キーボード操作、検索範囲は送信時に固定し fitBounds は結果表示時の地図サイズを使うこと、ピンと画面外候補の選択。評価と Google の星、営業時間・リンク・出典、投稿者リンク欠損、検索の割当・サーバーエラー・セッション上限。 |
| `verify-search-viewport.mjs`                       | 初回検索後に離れた地域へ移動・ズームし、地図に切り替えて即送信。地図の範囲確定待ち、候補への切替による待機取消、送信後の移動やシート操作を経てもチャットの viewport と手動検索の rectangle が送信時の地域を指すことを実際の POST 本文で検証。 |

`root-fixture.mjs` はシナリオごとに新しいブラウザコンテキストを作り、サービスワーカーを無効にする。外部リクエスト・未登録の API・ページ例外は失敗扱い。`maps-mock.js` は Google Maps の描画・位置・サイズ変更、`places-routes.mjs` は一括検索の候補と口コミを再現する。チャットは本物のブラウザ transport にモックの tool result をストリームする。各 API の送信内容とセッション・実行 UUID を記録して検証する。

`verify-keyboard.mjs` は、スマホでキーボードが開閉した際の表示領域の縮小・上下移動を模擬し、入力欄と地図の位置・元のシート高への復帰を検証する。料金の予約・精算、Routes の上流形式、実際に歩ける経路、実機のキーボードや指の感触はこのブラウザ検証の対象外。API の内部処理は `src/lib/` の単体テストで確認する。

**過去の記録:** `*results.json`、`*.log`、`docs/img/detail-panel/` と[旧詳細パネル検証報告](../docs/verification-detail-panel.md) は、旧画面を検証した時点の証跡。現行スイートはこれらを更新せず、結果を標準出力に表示する。旧ヒストグラム・常時表示の手動フォーム・旧シート寸法へのアサーションは現行画面には適用しない。
