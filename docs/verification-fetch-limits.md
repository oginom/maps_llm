## 見つかった不具合

### 1. 上端・右端の店舗詳細が画面外にはみ出す

再現: テストの `ui-observations` で12候補を検索し、上段右端の `ux-4` ピン（画面の x=82%、y=17%）をクリックする。

期待: 店名・閉じるボタン・本文が画面内で読めるように位置を調整するか、詳細パネルへ表示する。

実際: phone の吹き出し矩形は x=219.8、y=-132.6、幅200、高さ236.1、右端419.8。上約133pxと右約30pxが画面外。desktop でも y=-140.1 で上約140pxが画面外。店名・閉じるボタンが見えない。[phone 証跡](img/fetch-limits/phone-overlay.png)・[desktop 証跡](img/fetch-limits/desktop-overlay.png)。

関連: `src/app/page.tsx:557` の `CustomOverlay.draw`、`:578` の親座標、`:584` の固定上向き translate。境界判定や表示方向の切替がない。

ここでの寸法は合成投影での実測。モックは draggable pane の原点を地図中央として、ピンと吹き出し先端が対応するようにしている。Google の実投影・パン後の配置まで再現した証拠ではない。コンテナ座標と draggable div 座標は別の API であるため混同しない。[Google Maps の投影 API 定義](https://developers.google.com/maps/documentation/javascript/reference/overlay-view#MapCanvasProjection)。

### 2. スマホで分布パネルが警告と追加取得ボタンを覆う

再現: phone で `ux-2` の詳細を OVER_QUERY_LIMIT にして初期取得を完了し、検索フォーム右のメニューを開く。

期待: 警告全文と次の取得操作を読めて操作できる配置。

実際: 右下の分布パネルが警告本文と「次の5件を評価」の大部分を覆う。パネルを閉じるまで読みにくく、操作範囲も狭くなる。[phone 証跡](img/fetch-limits/phone-distribution.png)。PCでは今回の配置でこの重なりはなかった。[desktop 証跡](img/fetch-limits/desktop-distribution.png)。

関連: `src/app/page.tsx:675` の固定フッター、`:684` の警告、`:689` の取得操作、`:787` の `drawerOpen` パネル（bottom=120、right=16、width=300、zIndex=1000）。警告・状態欄が増えた高さを分布パネルの配置に反映していない。

## 未検証

- 実 Google Maps / Places / OpenAI の接続、割当残数、課金、分析品質。ユーザー指定に従い一切呼び出していない。
- Google の本物の投影・pane・自動パン、ズーム、タイル、実地理範囲への fitBounds。モックの配置は固定で、UI端の問題の再現用に限る。
- スマホ実機、Safari / Firefox、タッチの連打、ソフトウェアキーボード、セーフエリア。今回は Chromium の指定2サイズのみ。
- Places `textSearch` 自体が返る前の別検索への切替。現行UIは `isSearching` / `searchInProgress` で次検索を禁止する。シナリオ5は別検索を開始できる詳細・分析フェーズで検証した。
- 旧検索と新検索に同じ place ID が含まれる条件、旧応答がエラーの場合、長時間待機後の再試行。今回の遅延テストは検索ごとに異なるID、成功応答で実施した。
- サーバーから OpenAI への処理・課金のキャンセル。確認したのはブラウザ側 fetch の中断までで、両APIルート自体はルーティング層で置換している。
