# セッション引き継ぎ

## 現在地

ログイン不要の個人用地図アプリ。渋谷付近に地図を合わせて「電源があるカフェ」と送ると、`search_places` が表示範囲内の候補を探す。地名を指定しても検索範囲は送信時の地図のまま。候補を選んだ後は[店舗詳細からその支店について質問](chat-minimal-flow.md#選択した店について質問する)できる。

手動フォームもチャットも、Text Search Enterprise + Atmosphere **1 回**で最大 20 店の候補・詳細情報・口コミを取得する。独立した Place Details ルート・台帳計上はない。候補を先に表示し、口コミ原文は会話モデルには渡さず、店舗別の採点に使う。色は Google の星ではなく条件スコア。[チャットの流れ](chat-minimal-flow.md)／[Places アダプター](places-new-adapter.md)

## ローカル確認後の変更

- **根拠は原文の番号で返す。** 店舗別の評価に口コミ本文の配列を送り、採点できた場合は根拠となる口コミ番号（1 始まり・重複なし・1〜3 件）を受け取る。各原文と投稿者は同じ口コミから表示する。根拠不足は `{ value: null, reviewNumbers: [] }` で、低得点や採点エラーとは別に扱う。
- **チャットは表示中の地図を使う。** 「電源があるカフェ」を送ると、地名を聞き返さず表示範囲で検索することを実モデルで確認した。
- **評価は自動で続く。** チャット・手動検索ともに、「次の 5 件」を押さずに最大 20 店まで。20 は成功件数の保証ではなく、重複しない候補への試行上限。予算や割当で止まる場合がある。
- **スマホの下部シートは上端をドラッグして高さを変える。** 指に追従し、離すと 3 段階のいずれかで止まる。ボタンでも操作できる。実機での操作感は未確認。
- **繰り返し検索のキャッシュは保留。** 検索全体の重複と店舗別の再採点を別々に測り、保存可能な項目と期限を確認してから判断する。[設計時の判断項目](ai-map-plan.md#cache-design)

その先の候補は同じ候補の条件変更・再評価、徒歩時間比較、経路・途中の店、商品取扱の Web 調査、途中下車駅の提案。周辺検索のツールは `search_places` のみで、店舗への質問は独立した API。

## 費用とデータの扱い

- 利用目標は約 $0.20 / セッション、月 5 回で約 $1。これは請求実績ではない。[予算台帳](budget-ledger.md)は月・セッション・実行単位で OpenAI 金額と呼出し回数を予約・精算する。セッション ID はブラウザ生成なので、全利用に対する上限は月の台帳で見る。
- Google 側の日次割当は検索 20 回。詳細 100 回と Legacy の共通枠 100 回は設定済みだが現行アプリでは使わない。OpenAI 組織の月 $10 上限は別設定。Cloud Run は最大 1、予算による自動停止は導入しない。[API 利用制限](api-limits.md)
- 口コミ原文を OpenAI に送り採点する方式を継続する判断は、規約上の許可確認ではない。[Phase 0 検証票](phase0-verification.md)参照。口コミ原文はアプリで永続化しない。OpenAI の `store: false` も全保持の排除を意味しない。TypeSafe AI「Jev」への変更は[見送り](dev-api-research.md)。

## 検証と運用

- [旧採点方式の実 API 記録](verification-bundled-search.md): 地名なしで候補 20 件が 3.965 秒、5 件目の採点が 6.877 秒、全 20 件が 13.449 秒。生成した抜粋の投稿者付き照合は 14 / 20 店、OpenAI 台帳 $0.007468、Google 定価参考額 $0.040（請求明細ではない）。番号方式での実 API 計測は未実施。
- 開発は Node 24.20.0 / pnpm。`pnpm lint`、`pnpm exec tsc --noEmit`、`node --test src/lib/*.test.mjs src/lib/budget/*.test.mjs`、`pnpm build`。[ブラウザ検証](../e2e/README.md)は外部 API をモックする。
- Cloud Run のサービスは `mapsllm`（`asia-northeast1`）。本番では Firestore の既定データベース・`roles/datastore.user`・セッションの TTL を使用。main への push は文書のみでも再デプロイを起こす。操作アカウント・本番 URL は git 管理外の `CLAUDE.local.md`、キーはローカル環境変数と GitHub Secrets を参照する。
